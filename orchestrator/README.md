# Orchestrate a company goal

Repository source for the globally installed `$orchestrate` skill. The active skill lives under `~/.agents/skills/orchestrate/`, so it is available from every company workspace. Keep this guide and its controller script aligned with the installed copy.

Use this workflow when the user asks for an overall company outcome that may require several issue, PR, or review conversations. The current conversation is the coordinator. Delegate each identified task to a separate Argus conversation through the controller, then control that conversation from here. An internal subagent or work performed in this coordinator conversation does not satisfy the separate-session requirement.

1. Resolve the company using `~/.agents/companies/index.md`, then read its `index.md`, `me.md`, project indexes, and applicable workflow guides. Name this coordinator conversation with the company name by running `node ~/.agents/skills/orchestrate/scripts/control.js rename-self --title <Company>`. If the conversation is not in Argus, continue without renaming.
2. Turn the goal into independently verifiable tasks and register it for the Argus Company goals view with `node ~/.agents/skills/orchestrate/scripts/control.js goal --company GMTrade --goal <stable-goal-key> --title "<short goal>"`. The coordinator may read company-level state to identify work and prepare separate code worktrees when edits could collide. Keep the Argus session workspace at the coordinator's working directory even when task files live in a worktree; put that worktree path in the worker prompt. Once an issue or PR is identified, put its current-description, complete-history, attachment, linked-document, and project-note checks in the worker's prompt. The worker performs those checks before changing task state or code; the coordinator checks its evidence and decisions.
3. Start a named external Argus session for each issue or PR before doing its task work. Run the controller from the coordinator session's working directory and omit `--workspace` so every new worker appears in Session History's This workspace tab. Use its short identifier and name in `--title`, for example `SCSOL-6 · Fee credit`, and a stable `--key` such as `SCSOL-6`. Run `node ~/.agents/skills/orchestrate/scripts/control.js run --company GMTrade --goal <stable-goal-key> --key SCSOL-6 --title "SCSOL-6 · Fee credit" --text-file <prepared-task-prompt>`. Different keys create separate Argus sessions even in the same directory. Confirm the returned session ID with `inspect`; tell the user how to find it in This workspace and Company goals. The controller preserves the worker's provider and model without changing global defaults. Run independent workers concurrently only when their files, worktrees, and external state do not conflict.
4. Control each worker until the requested task is verified: read the streamed result and status from `run`, use `inspect` for its current session and pending interaction, `send` for follow-up instructions in that same session, and `status` for the goal's workers. If a command keeps running, retain and poll that process to see progress. A `needs-input` result means the worker is paused. Check whether the user already authorized the exact operation; if so, use `respond --company <company> --key <worker-key> --id <interaction-id> --response '{"decision":"accept"}'` for a Codex approval. Otherwise obtain the user's answer, then respond with that decision or the provider's requested question shape. `respond` streams the resumed turn; handle each further interaction. Do not invent approval fields or guess consent. If a worker fails, inspect and recover in its named session; do not transfer implementation or tests to the coordinator. Use `stop` only for cancellation or replacement.
5. Verify every requested outcome from fresh tracker, code-host, test, and communication state. Send corrections back to the same worker with `send`; the coordinator does not implement them. Apply the company's handoff guide, including required links and fields. A worker's final message is evidence to review, not proof of completion. When a finished task yielded reusable findings, invoke `/update-notes` in its worker session and check the saved notes. Mark the goal `--status done` only after all requested outcomes are verified. Finish with a concise goal status, remaining blockers, and the session identifiers.

The controller stores only session metadata in `~/.agents/runs/orchestrate/`. Provider transcripts and credentials remain in their native locations. Do not put secrets in prompts saved as files or in checkpoint state. Use `--mode edit` by default; select `--mode full-access` only when the specific work needs it and the user has authorized that scope. Use an explicit `--workspace` only if the user asks for a worker in another Argus workspace; a code worktree alone is not a reason to change it.
