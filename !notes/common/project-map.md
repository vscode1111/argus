Filters on `readyState === 1`, the **same filter the count uses**, so the number and the list it opens can never disagree - which is also why a socket with no recorded metadata is still listed, with `connectedAt: 0` rendered as `-`, rather than skipped. `closeClient(sockets, id, self)` disconnects one of them with the terminal close code 4001 (see the Connected client list convention below: the id is validated against the live set, and a self-close is deferred a tick so the reply gets out first). Pure helpers, exported for the spec: `normalizeAddress` (`::ffff:192.168.0.12` -> `192.168.0.12`, `::1` -> `127.0.0.1`), `isLocalAddress` (what the "remote" badge is decided by), `clientKind` (vscode-webview Origin / `client=browser` / else **unknown**, never guessed into one of the two), `deviceFromUserAgent` (ordered so iPhone beats the "Mac OS X" its own UA carries and Android beats its "Linux")
    auth.ts             - Remote-access credentials and sessions. Only peers that are NOT on this machine meet any of it: the decision is `isLocalAddress(req.socket.remoteAddress)`, **never the Origin header** - Origin is client-supplied, and a request that simply omitted it used to be treated as local from anywhere (measured, see the probe in !notes/tasks/remote-access-auth/scripts/). Holds the credential in its own `~/.Codex/argus-auth.json` at mode 600 rather than in argus.json, because that config is written by `updateSettings`, a bulk merge filtered only by the DEFAULT_CONFIG allowlist - a password must not be reachable by the path that writes a checkbox. scrypt + 16-byte salt with `timingSafeEqual`, re-read from disk on **every** check (no mtime cache, so a password change binds on the next request), sessions in a module-level Map (they die with the process by design), and a per-address lockout of 5 failures then 30s doubling to 15 min that a success clears. `setPassword` requires the current password whenever one exists, so a hijacked session cannot lock the owner out, and it drops every issued session

    filePreview.ts      - Shared file preview reader (path validation, image detection, used by both backend and extension); stats before reading, so a **directory** answers with `{entries, parent, truncated}` (folders first then files, case-insensitive, capped at MAX_DIR_ENTRIES 1000, sizes stat'd only for entries surviving the cap) instead of failing with EISDIR

Two modes: **browse** (empty query, or one naming an existing directory - it must end in `/`, which is what picking a folder inserts) lists ONE directory's immediate children, containment-guarded so `../` cannot leave the workspace; **search** (any other query) walks recursively with a substring match, capped, skipping node_modules/.git/etc. The reply carries `mode`/`base`/`parent` so the UI can render an up row, and `parent` is derived from the query's directory prefix in search mode too (hand-editing a path has no trailing slash, so it IS a search, and returning null there lost the back row). `childCount` on every directory, because an `@folder` inlines the contents of everything under it. `mentionFor()` decides quoting. Collation pinned to `Intl.Collator('en', {numeric:true})` - the daemon resolves to ru-RU, where Cyrillic sorts before Latin and a listing then disagrees with Windows Explorer

A `busy` port (accepts, but /health did not answer in time, i.e. a stalled daemon) leaves both process and file alone and exits 1; a failed kill leaves the file; a successful kill is verified with `waitGone` before the file goes. The busy/down rule is duplicated from `daemonInfo.ts` rather than imported on purpose - `yarn daemon:stop` has to work before anything is compiled, so this script stays dependency-free
